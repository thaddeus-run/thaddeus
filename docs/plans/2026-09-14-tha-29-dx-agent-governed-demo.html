Goal and architecture

Make the existing first-run instructions reproducible, enforce the shared release version, and ship make demo as a live demonstration of agent-governed changes. The clone-path guidance is already corrected by THA-27; preserve it and exercise both destination forms.

A Bun driver starts the compiled CLI server, initializes separate temporary identities, and runs every actor command through that same executable over HTTP. The owner signs shared-head changes; a distinct reviewer vetoes a candidate through an explicit local checkout handoff. An isolated second repository proves that the agent's operation budget is enforced.

Two small CLI changes support truthful provenance: push -m and rename -m accept a constrained actor-kind declaration. A dependency-free version checker covers source manifests and lock entries. Release preflight verifies the selected tag and fixes one source commit for all jobs; native runners check the built binary artifacts before publication.

Tech stack: existing TypeScript, Bun 1.3.14, Moon 2.3.3, Rust 1.95.0, GitHub Actions, and a thin Make entry point. No new package dependency or recording tool is required.

  2. Implement the parser and validate before mutation 
    export type CliActorKindResult = { kind: string } | { error: string };

// Validate a declaration before either command commits edits or uploads data.
export function parseCliActorKind(
  raw: string | undefined,
  message: string | undefined,
): CliActorKindResult {
  if (raw === undefined) return { kind: 'human' };
  if (raw !== 'human' &&
      !/^agent:[A-Za-z0-9][A-Za-z0-9._-]*@[A-Za-z0-9][A-Za-z0-9._+-]*$/.test(raw)) {
    return { error: 'invalid --actor-kind: use human or agent:<name>@<version>' };
  }
  if (message === undefined || message.trim().length === 0) {
    return { error: '--actor-kind requires a nonempty -m message' };
  }
  return { kind: raw };
}

The narrated demo

Use one generated owner, agent, and reviewer identity. The agent is a deterministic script. Its declaration is agent:thaddeus-demo@<checkout-version>, where the version comes from the actual compiled executable. A printed command always corresponds to an executed command.

Create one temporary root. Under it, keep actor homes, server data, a transcript, and separate checkouts for accepted work, protected attempts, review candidates, and readback. Use argument arrays and the home-isolation pattern from packages/cli/test/init-compile.test.ts in child environments only. Resolve the executable from packages/cli/release/; the driver does not search PATH for Thaddeus.

Start thaddeus serve --data <owned-server-directory> --port 0. Parse its actual serving URL while continuously draining both streams, then require GET /repos to return 200 and the JSON object { repos: [], owners: {}, nextCursor: null }. Startup has a 15-second deadline. Each finite CLI command has a 15-second deadline, excluding build time; the full demonstration has a 120-second deadline. A premature server exit is a demo failure.

The driver connects through localhost. This does not claim the existing server binds exclusively to loopback; --host is an attestation option, not a bind-address option.

The candidate's why verifies before review. Veto JSON identifies the reviewer, exact reason, verified signature, and active lifecycle. Land returns 1 for veto; fresh main still has accepted greeting and auth bytes. The earlier exhaustion in another repository did not consume this repo's remaining operation allowance.

The same-machine handoff is explicit in narration: it supplies access to the candidate checkout, while the reviewer grant supplies authority to veto. Do not imply that the grant supplies decryption rights or that a fresh reviewer clone can obtain the pending operation.

Each rejected proposal starts from a fresh accepted-main clone. Deleting a dirty file from a previously rejected checkout does not remove its committed ancestry. The protected rejection, budget exhaustion, and reviewer veto must each fail for their own stated reason.

For every upload, assert the expected nonzero accepted operation/object/provenance counts for that fixture and reject any rejected N item(s) line.
