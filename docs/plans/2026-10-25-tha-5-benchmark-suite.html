THA-5 Benchmark Suite and FileBackend Baseline — Implementation Plan

A deterministic benchmark suite for Thaddeus, a recorded baseline of today's FileBackend, and a report-only PR regression check whose thresholds come from a measured noise study. Spec: docs/superpowers/specs/2026-10-25-tha-5-benchmark-suite-design.md, committed in 4d4b7a8.

Goal and shape

Goal: Measure what ships today, so THA-21 has a "before" and a later website figure has a committed run to link to.

Architecture: A new private moon project, bench/, holds four parts:

  • a pure, seeded fixture plan, with a manifest hash that proves the inputs are identical
  • a runner that executes each case in its own subprocess, so it can record peak memory and enforce time budgets
  • a library suite that runs in-process
  • an end-to-end suite that drives the real thaddeus binary against thaddeus serve

A small compare and noise module turns base and head runs into a GitHub job summary.

Tech stack: Bun, TypeScript, bun:test, moon, and ajv for JSON Schema validation. ajv is already in bun.lock at 8.20.0 as a transitive dependency, and gets added to the root catalog at that pin.

Global constraints
  • Package @thaddeus.run/bench has "private": true and is never published. Dependencies come from the root workspaces.catalog or workspace:*.
  • Fixture table: small has 100 files, 1,000 ops, 1 author and 1 view. Medium has 2,000 files, 20,000 ops, 10 authors and 50 views. Stress has 20,000 files, 200,000 ops, 100 authors and 500 views.
  • The sweep doubles history length: 1k, 2k, 4k … ops. It reports an exponent together with its R².
  • A budget overrun is recorded as exceeded <budget> at n = X and an out-of-memory as oom at n = X. Both are results. Neither hangs nor skips the run.
  • Every write, push and land result carries durability: "none (FileBackend renames atomically, no fsync)".
  • The machine block names the host as a shared, virtualized guest: KVM, 4 vCPU AMD EPYC Rome, 7 GB RAM.
  • bench:record refuses to start when the 1-minute load average is above 0.5, or when less than 2 GiB is available. It records both values in the result.
  • Results go to bench/results/<machine>/<date>-<short-commit>.json, and the current reference run is copied to bench/results/<machine>/baseline.json.
  • Cold cases run twice in bench:record: once with pageCache: "warm" and once with "dropped" (echo 3 > /proc/sys/vm/drop_caches). The PR check runs warm only.
  • The end-to-end suite uses the shipped serve defaults and raises only the limits a case hits. The exact flags go in serveFlags.
  • PR thresholds are the 99th percentile of the head/base median ratio from an A/A noise study. The check is a separate workflow and is not part of ci-passed. It writes a job summary and an artifact, and posts no PR comment.
  • Results are compared only when the case id, case version and manifest hash all match. Anything else is shown as "new or changed, not compared".
  • Commits follow Conventional Commits. Run moon run root:format root:lint and moonx bench:typecheck bench:test before every commit. A non-trivial helper gets a short comment directly above it, aimed at a reader new to the code.
Review focus
  • Setup fails, not the timed part. Building a stress fixture can run out of memory or time on a 7 GB host. Expected: the case is recorded with phase: "setup" and the right status, and the run continues. The test lives in Task 4.
  • Partial fixture cache after a killed run. A budget kill during materialization must never leave a cache directory that a later run trusts. Expected: the cache is built in a temporary directory and renamed into place along with a .complete marker that holds the manifest hash. Anything without the marker is rebuilt. The test lives in Task 2.
  • Hard-link copies mutating the cache. Write cases work on a cp -al copy. Expected: the cached fixture's file count and bytes are unchanged afterwards. The test lives in Task 5.
  • Record preflight. A dirty tree under packages/ or bench/, or sudo -n being unavailable for dropping the page cache, must stop bench:record before any case runs. That keeps a results file from naming a commit it didn't measure, and keeps a run from failing halfway. The test lives in Task 7.
  • Status differs between base and head. Base exceeded with head ok counts as an improvement. Base ok with head exceeded or oom counts as a regression, whatever the threshold. The test lives in Task 9.

For agentic workers: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Run export AGENT=1 first.

  3. Implement.
    • The parent spawns bun bench/src/child.ts with a JSON argument: { registry, id, fixtureSpec, repeats, warmup, pageCache }.
    • per-case isolation means one child process runs setup once, then the warm-ups, then the timed repeats. per-sample means one child per timed sample, and beforeSample runs in the parent before each spawn. That hook is where Task 7 drops the page cache.
    • The child prints {"phase":"setup"} when it starts setup and {"phase":"run"} when it starts timing, so a budget kill can name the phase. At the end it prints a final JSON line with samplesMs, extra and peakRssBytes, where peakRssBytes = process.resourceUsage().maxRSS * 1024.
    • The budget covers the whole child, setup included, and on expiry the parent sends SIGKILL and records exceeded.
    • A SIGKILL the parent didn't send, or stderr matching /out of memory|JavaScript heap|Allocation failed/i, is recorded as oom. Any other non-zero exit is error, with the last 2 KB of stderr as note.
    • Throughput is computed from the summed extra over the summed time.
    • runSweep stops at the first size that doesn't come back ok, sets failedAtN, and fits the exponent over the points that did.
