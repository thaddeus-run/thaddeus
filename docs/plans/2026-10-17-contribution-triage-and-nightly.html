Contribution triage and nightly builds: implementation plan

Bring the contribution, triage, CI and release-channel setup of pingdotgg/t3code to Thaddeus, minus the parts that only fit an Electron, mobile or Vercel product. Stacked on the THA-33 branch at e590463.

Goal and shape

Goal: outside people and agents get a clear contribution policy, PR and issue forms, vouch and size labels, and a triage skill. CI gates every suite that passes. Users can opt into nightly CLI builds, and a mismatched CLI and server say so plainly instead of failing with a generic 401 or 404.

Architecture: repository files and GitHub workflows copy t3code's shapes with Thaddeus names. One wire-protocol constant shared through @thaddeus.run/server/protocol lets the server refuse a mismatched client with a 426, and a public GET /version reports both versions. The existing tag-driven release.yml gains a scheduled nightly channel that rewrites the shared release version in the runner before building, so root:version-check stays the single guard. Nightly and alpha CLIs talk to the same servers, as t3code's channels share one backend.

Tech stack: GitHub Actions with actions/github-script@v8 and mitchellh/vouch v1.5.0, Bun and moon, TypeScript in packages/server, packages/client and packages/cli.

Global constraints
  • Use bun and moon only. No new dependency without a root catalog entry; this plan adds none.
  • Commits follow Conventional Commits 1.0.0 and end with the attribution line.
  • Prose wraps at 80 columns (oxfmt proseWrap: always). Run moon run root:format root:lint before every commit.
  • Pin third-party actions that run with write tokens to a commit SHA.
  • A pull_request_target job never checks out, installs or runs PR code.
  • Copy t3code text only where it fits. Name the source commit 2fae0f9 in each adapted file's first comment.

For agentic workers: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.
