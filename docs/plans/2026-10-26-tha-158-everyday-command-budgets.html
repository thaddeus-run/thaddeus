THA-158: everyday-command latency budgets against git, gated in CI

Build order 005a. This plan adds git baselines next to the THA-5 benchmark suite, writes each everyday command's target down as a number in milliseconds and as a multiple of git, and adds a required CI job that fails when thaddeus gets slower relative to git. It starts from a898b8a on main.

Changed during build
  • The gate checks each command's thaddeus p50, not the thaddeus/git ratio. git's own median moved by tens of percent between runs, more than the thaddeus slowdowns the gate must catch, so a ratio ceiling would have had to be wider than them. The git multiple is still reported and never gated.
  • Ceilings are kept per CPU model with a pooled fallback, and are calibrated across 20 GitHub runners in a matrix (bench ceilings), not on one runner. GitHub hands out several CPU models, and status on one runs about twice as fast as on another.
  • Ceilings use a Student-t quantile, and git cases take at least 25 samples (BenchCase.minRepeats).
  • fastImportStream became the generator fastImportChunks, piped into git fast-import, so the stress fixture builds in bounded memory.
  • The fixture working copy writes the owner-signed head records a clone holds and drops the fork views, so status opens the same store shape as a clone.
  • e2e.workspace and git.worktree are warm cases. Only git.clone is cold.

Goal and shape

Goal. Each everyday command gets a median target, an observed median on a populated repository, a measured multiple of git on the same repository, and a CI check that fails when that multiple gets worse.

Architecture. A new everyday suite in bench/ holds the git baseline cases and the thaddeus cases that need no server (status, diff). The git side replays the same fixture plan through git fast-import, so both tools see the same files and the same number of changes. The thaddeus commands that talk to a server reuse the THA-5 e2e cases. A budgets file pairs each thaddeus case with its git case. The CI gate compares the thaddeus/git ratio on the runner against a ceiling taken from a calibration study on GitHub runners. That uses the same lognormal, Bonferroni-split bound the PR check already uses for its thresholds.

Tech stack. Bun and TypeScript in bench/, the compiled thaddeus binary, git 2.x, GitHub Actions. No new dependencies.

Global constraints
  • Every e2e and everyday case runs on the serial fixture variant (small-serial and so on), because the shipped server refuses lands into a main that holds a conflict.
  • Do not mock or stub anything to make a case pass. A case that cannot run records exceeded, oom or error, and that status is the result.
  • Thresholds come from a measured study, never from a percentage someone picked. This is the THA-5 rule and the gate follows it.
  • A figure in a document either carries the word "target" or links to the run that produced it (architecture contract section 5).
  • Verification baseline after every code task: moon run root:format root:lint, moonx bench:typecheck, moonx bench:test. Run export AGENT=1 first.
  • Commits follow Conventional Commits with the bench or ci scope, as in recent history (feat(bench): ..., ci(bench): ...).

Decisions this plan makes

These were open in the issue. Each one is a default I picked so the work can go ahead without waiting on an answer. Change any of them in review.

Question Decision
What counts as "commit" thaddeus push --no-land of 10 files (e2e.push.10), against git add -A, git commit and git push to a bare repository, summed. thaddeus has no local-only commit, so the git baseline includes the push too.
What counts as "checkout" thaddeus workspace bench-ws <dir> (new case e2e.workspace), against git worktree add <dir> bench-ws. Both open a branch in a new directory, which is the thaddeus model.
What counts as "pull/sync" e2e.pull, where a second identity pulls a 10-file change, against git pull --ff-only of a 10-file commit.
Checkout at the start of a CI job e2e.checkout.cold (thaddeus clone into an empty directory, fresh home) with the page cache dropped, against git clone --depth 1 file://... with the page cache dropped. Depth 1 is what actions/checkout does by default.
Developer and agent environments Developer means one command at a time on the machine. Agent means 8 agents on one 4-vCPU host, each in its own working copy, all running the command at once. The sample is the time until the last of the 8 finishes. The agent rows cover status and diff, which run locally. Agent load on server commands needs concurrent writers on one server, which is THA-118's replayable agent workload (build order 006). Those rows are listed as unmeasured and owned by THA-118.
Rebase It gets a target row, marked unmeasured because the command does not exist, and THA-11 owns it. Timing land instead would put a number on a different operation.
Which fixture the absolute targets apply to medium-serial (2,000 paths, 20,000 ops, 10 authors), which the bench README calls "a real active repository". Multiples are reported on every fixture that ran. stress-serial is reported too.
Target multiples 1.0 for every row, meaning "no slower than git". The issue asks for an advantage over git, and parity is the first number that can show one. Nothing measured supports a tighter multiple yet.
What the gate fails on A thaddeus/git ratio above its calibrated ceiling, a gated case that no longer finishes ok, a missing ceilings file, or ceilings recorded for other case versions. A missed target does not fail the build. It is reported with the issue that owns the fix, because today's numbers miss most targets and a gate that is red on every PR would only get switched off.
Where the gate runs A new job in ci.yml, listed in ci-passed's needs, so it is required. It runs on small-serial, warm, 3 repeats and 1 warm-up. That is the largest fixture the server cases can seed today.
Where observed numbers are kept The CI ceilings file holds the observed ratios from the calibration study and is committed. The KVM run of Task 9 goes in the PR body and the Linear issue, tagged with its commit. The bench README says a citable bench/results/ file is recorded from the merged main commit in a separate PR, because merges rebase. This plan follows that rule and leaves the post-merge record as a follow-up.

    // The plaintext main tree of a serial plan, and the fixed edit the
// status and diff cases apply to it. Both the thaddeus and the git side
// apply the same edit to the same tree.
export const EDIT_FILES = 10;
const EDIT_LINE = '// bench edit\n';

export function mainTree(plan: FixturePlan): Map<string, Uint8Array> {
  if (plan.spec.variant !== 'serial') {
    throw new Error(`mainTree needs a serial plan, got ${plan.spec.name}`);
  }
  let main = new Map<string, Uint8Array>();
  const open = new Map<string, Map<string, Uint8Array>>();
  const tree = (view: string) => (view === 'main' ? main : open.get(view));
  for (const step of plan.steps) {
    if (step.kind === 'fork') open.set(step.view, new Map(main));
    else if (step.kind === 'land') {
      const landed = open.get(step.from);
      if (landed !== undefined) main = landed;
      open.delete(step.from);
    } else if (step.kind === 'write') tree(step.view)?.set(step.path, contentFor(step));
    else tree(step.view)?.delete(step.path);
  }
  return main;
}

export function editPaths(plan: FixturePlan): string[] {
  return [...mainTree(plan).keys()].sort().slice(0, EDIT_FILES);
}

export function applyEdit(dir: string, paths: readonly string[]): void {
  for (const path of paths) appendFileSync(join(dir, path), EDIT_LINE);
}

    export const GIT_SEED_VERSION = 1;

export function fastImportStream(plan: FixturePlan): Uint8Array {
  const enc = new TextEncoder();
  const parts: Uint8Array[] = [];
  const text = (s: string) => parts.push(enc.encode(s));
  const tips = new Map<string, number>();
  let mark = 0;
  for (const step of plan.steps) {
    if (step.kind === 'fork') {
      const tip = tips.get(step.from);
      if (tip === undefined) tips.delete(step.view);
      else tips.set(step.view, tip);
      continue;
    }
    if (step.kind === 'land') {
      const tip = tips.get(step.from);
      if (tip === undefined) continue;
      tips.set('main', tip);
      text(`reset refs/heads/main\nfrom :${tip}\n\n`);
      continue;
    }
    const when = Math.floor(Date.parse(step.at) / 1000);
    const who = `author-${step.author} <author-${step.author}@bench.invalid> ${when} +0000`;
    const message = `${step.kind} ${step.path}\n`;
    mark += 1;
    text(`commit refs/heads/${step.view}\nmark :${mark}\nauthor ${who}\ncommitter ${who}\n`);
    text(`data ${message.length}\n${message}`);
    const parent = tips.get(step.view);
    if (parent !== undefined) text(`from :${parent}\n`);
    if (step.kind === 'write') {
      const bytes = contentFor(step);
      text(`M 100644 inline ${step.path}\ndata ${bytes.length}\n`);
      parts.push(bytes);
      text('\n');
    } else {
      text(`D ${step.path}\n`);
    }
    text('\n');
    tips.set(step.view, mark);
  }
  return concatBytes(parts);
}

    // A working copy as `thaddeus clone` leaves one, built without a server:
// the fixture's store hard-linked into .thaddeus/store, main written to
// disk as the owner reads it, and a config whose base is main's heads.
// status and diff only read the store and the disk, so they cannot tell
// it from a clone. Commands that talk to a server would fail on the
// unused address, and no case runs them here.
export const UNUSED_SERVER = 'http://127.0.0.1:9';

export async function thadWorkingCopy(plan: FixturePlan, dir: string): Promise<void> {
  await ready();
  const store = join(dir, '.thaddeus', 'store');
  await linkCopy(await fixtureDir(plan), store);
  rmSync(join(store, COMPLETE), { force: true });
  const [owner] = authorsOf(plan);
  const repo = await new Platform().openDurable('bench', new FileBackend(store));
  for (const [path, entry] of repo.log.materialize('main', owner)) {
    if (entry.ref === null) continue;
    const full = join(dir, path);
    mkdirSync(dirname(full), { recursive: true });
    writeFileSync(full, await repo.store.get(entry.ref, owner));
  }
  const config = { server: UNUSED_SERVER, repo: 'bench', base: [...repo.heads('main')], view: 'main' };
  writeFileSync(join(dir, '.thaddeus', 'config.json'), `${JSON.stringify(config, null, 2)}\n`);
}

    // What the CI gate measures: every case a budget row names, on small,
// warm, 3 repeats and 1 warm-up. Server cases cannot seed medium until
// THA-21, so small is the largest fixture the gate can run today.
export const GATE_METHOD = {
  suite: 'all' as const, fixtures: ['small'], sweeps: false,
  pageCache: ['warm' as const], repeats: 3, warmup: 1, budgetMs: 300_000,
};

// The gate's ceiling for each ratio key: the largest thaddeus/git ratio
// runner noise plausibly produces, from a calibration study on the CI
// runner. The same lognormal bound and Bonferroni split as
// deriveThresholds, nominally a 1% chance that an unchanged PR fails, but
// not floored at 1: a command that is faster than git keeps that lead.
export function deriveCeilings(
  ratios: Record<string, number[]>,
  meta: { studiedAt: string; runnerImage: string; runs: number;
          caseVersions: Record<string, number> }
): Ceilings {
  const studied = Object.entries(ratios).filter(([, r]) => r.length >= 3);
  const z = studied.length === 0 ? null : normalQuantile(1 - 0.01 / studied.length);
  const perKey: Record<string, number> = {};
  for (const [key, r] of studied) {
    const { mu, sigma } = logMeanStdev(r);
    perKey[key] = Math.exp(mu + (z ?? 0) * sigma);
  }
  return { ...meta, method: 'lognormal-family-wise', familySize: studied.length, z, perKey };
}
